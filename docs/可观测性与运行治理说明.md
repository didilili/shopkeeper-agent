# 可观测性与运行治理说明

## 1. 目标与边界

本模块为 HTTP、SSE 问数、LangGraph 节点和外部依赖提供统一指标、结构化审计
事件和动态健康检查。指标只使用代码内固定的低基数标签，不记录用户问题、
request_id、SQL、表名、API Key、召回值或原始异常文本。

当前指标保存在单个 Python 进程内。多 Worker 或多副本部署应使用 Prometheus
multiprocess 模式、集中式采集或后续 OpenTelemetry Collector。

## 2. 运行端点

- `GET /api/health/live`：只表示 HTTP 进程可响应，不检查外部依赖。
- `GET /api/health/ready`：应用资源初始化完成且缓存的依赖探测全部通过时返回 200，
  否则返回 503；响应不暴露具体依赖信息。
- `GET /api/diagnostics`：返回各依赖的 `up/down`、探测耗时、检查时间和有限错误
  分类。
- `GET /metrics`：Prometheus 文本格式指标。

诊断和指标端点复用 `X-API-Key` 访问控制。生产环境强制启用 API Key；开发环境
关闭认证时，仅适合本地使用，不应把端点直接暴露到公网。

## 3. 依赖健康检查

健康服务并发检查：

- Meta MySQL、DW MySQL：`SELECT 1`；
- Qdrant：读取 collection 列表；
- Elasticsearch：`ping`；
- TEI Embedding：调用 `/health`，不重复生成向量。

每个探测都有独立超时。结果按 TTL 缓存，并使用异步锁合并并发刷新，避免容器
平台高频探针放大为下游请求风暴。详细响应不会包含连接地址、数据库名或原始异常。

## 4. 指标

主要指标包括：

- `shopkeeper_http_requests_total`
- `shopkeeper_http_response_duration_seconds`
- `shopkeeper_query_streams_total`
- `shopkeeper_query_stream_duration_seconds`
- `shopkeeper_agent_nodes_total`
- `shopkeeper_agent_node_duration_seconds`
- `shopkeeper_external_operations_total`
- `shopkeeper_external_operation_duration_seconds`
- `shopkeeper_dependency_up`
- `shopkeeper_access_rejections_total`
- `shopkeeper_sql_result_rows`
- `shopkeeper_sql_corrections_total`

HTTP 中间件统计响应对象建立时间。SSE 的完整生命周期由 `QueryService` 内部单独
统计，覆盖正常完成、业务异常和客户端取消。

## 5. 审计日志

生产环境默认输出 JSON 日志。审计事件使用固定字段：

```text
event, component, operation, outcome, error_category, duration_ms
```

生成、修正、校验和执行 SQL 时仅记录 SHA-256 截断指纹、SQL 长度、修正次数和
结果行数，不记录 SQL 正文或结果内容。召回日志只记录候选数量，不记录查询词、
匹配值或完整候选列表。

## 6. 配置

```text
OBSERVABILITY_ENABLED=true
METRICS_ENABLED=true
DIAGNOSTICS_ENABLED=true
HEALTH_TIMEOUT_SECONDS=3
HEALTH_CACHE_TTL_SECONDS=10
SLOW_QUERY_THRESHOLD_SECONDS=10
LOG_STRUCTURED=false
```

生产环境配置会把 `LOG_STRUCTURED` 默认覆盖为 `true`。

## 7. 验收要求

- 外部依赖全部可用时 readiness 为 200；
- 任一依赖停止后 readiness 在缓存过期后变为 503；
- 依赖恢复后 readiness 自动恢复；
- liveness 不受外部依赖状态影响；
- 未授权诊断和指标请求返回 401；
- 指标和日志中不存在用户问题、SQL 正文、结果数据或密钥。

## 8. 在线故障演练记录

2026-07-23 使用本地 Docker 依赖完成在线验收：

- 正常态下 `/api/health/live`、`/api/health/ready` 和
  `/api/diagnostics` 均返回 200，五项依赖均为 `up`；
- 停止 Qdrant 并等待健康缓存过期后，liveness 保持 200，readiness 返回 503，
  诊断仅返回 `qdrant=down` 和有限分类 `dependency_timeout`；
- 重新启动 Qdrant 后，readiness 自动恢复为 200，诊断恢复为 `healthy`，
  `shopkeeper_dependency_up{dependency="qdrant"}` 恢复为 `1`。
