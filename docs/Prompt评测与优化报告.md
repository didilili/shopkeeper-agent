# Prompt 评测与优化报告

评测日期：2026-07-22

## 评测范围

评测集位于 `evals/prompt_cases.yaml`，使用项目真实的订单事实表、商品、客户、
地区、日期维度以及 GMV、AOV 指标，共包含 10 个案例，覆盖全部 7 个 Prompt：

- 字段、指标、字段值三路召回
- 指标和表字段筛选
- SQL 生成
- SQL 错误修正

案例覆盖品类 GMV、会员等级 AOV、华东与华为实体值、无指标问题、跨表 JOIN、
时间过滤、错误字段修正和只读 SQL 安全约束。

## 当前结果

离线契约评测：10/10，通过率 100%。

在线语义评测：10/10，通过率 100%，评测模型为 `sql_agent` 当前部署。

离线评测验证：

- Prompt 已注册且版本、文件路径有效
- 评测输入与模板变量完全一致
- 每个 Prompt 均渲染为 System + Human 两条消息
- 输出协议与注册表声明一致

在线评测结果确认：

- 字段召回覆盖品类、金额、日期、会员等级等必需概念
- 指标召回命中成交总额、订单总额和 GMV
- 字段值召回只保留华东、华为等真实候选值
- 指标筛选正确选择 GMV，并在无度量问题中返回空数组
- 表筛选保留事实表、商品表、日期表及两侧连接键
- 两个 SQL 生成案例均包含正确 JOIN、聚合、分组和结果别名
- SQL 修正把不存在的 `sale_amount` 最小替换为 `order_amount`
- 所有 SQL 均通过单语句和只读安全检查

当前 100% 表示这 10 个已定义案例全部达标，不等同于面对任意用户问题都能达到
100% 准确率。后续新增 Schema、指标或业务问法时，需要同步扩充评测集。

## 静态审计发现的问题

1. 原示例使用实习生转正场景，与当前电商数据域不一致。
2. 字段值召回把相对时间当作数据库取值，容易给 ES 检索引入噪声。
3. 指标和表筛选的空结果规则不够统一，可能迫使模型兜底选择。
4. SQL 生成允许使用通用业务常识，可能绕过受控指标和 Schema。
5. SQL 生成对 JOIN、时间字段、GROUP BY 和别名要求不够集中。
6. AOV 元数据描述为平均订单金额，但依赖字段误配为订单数量。

## 已完成优化

- 七份 Prompt 全部替换为真实电商示例。
- 明确字段、指标、实体值三种召回对象的边界。
- 字段值召回不再输出相对时间和度量概念。
- 指标与表筛选明确允许 `[]` 和 `{}`。
- SQL 只能依赖用户问题、指标定义、候选 Schema 和数据库环境。
- 强化 JOIN 键、日期、GROUP BY、结果别名和最小查询要求。
- SQL 修正强调最小修改和保持业务口径。
- 修正 AOV 的依赖字段为 `fact_order.order_amount`。

## 在线回归结论

本轮在线评测没有失败案例，因此未继续无依据修改 Prompt。当前七份文案作为
`1.0.0` 基线保留；后续只有在新增案例失败或线上链路出现可复现问题时，才调整
文案并提升对应 Prompt 版本。

## 运行方式

不调用模型、不消耗额度：

```bash
uv run python -m app.scripts.evaluate_prompts --mode offline
```

填写真实 `LLM_API_KEY` 后运行在线语义评测：

```bash
uv run python -m app.scripts.evaluate_prompts --mode live
```

只评测 SQL 生成：

```bash
uv run python -m app.scripts.evaluate_prompts --mode live --prompt generate_sql
```

在线报告会逐案例检查必需概念、精确指标选择、必需表字段、SQL 关键片段和禁止项，
并以非零退出码表示存在失败案例，方便后续接入 CI。
